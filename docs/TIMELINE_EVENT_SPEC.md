# 时间轴事件规格

## 1. 核心定义

时间轴事件是《视频课程套壳》的核心数据模型。

它描述在主课程视频播放到某个时间点时，最终视频 HUD 中哪些模块发生变化，例如地图节点点亮、任务切换、重点提示弹出、底部阶段条进入新阶段等。

第一版采用用户手动配置时间点，不做 AI 自动识别。

## 2. 事件设计原则

### 2.1 时间点由用户显式配置

每个关键界面变化都应有明确触发时间。用户可以通过编辑器播放器拖动到目标时间，再点击“使用当前时间”写入。

### 2.2 主视频是时间基准

所有事件都以主课程视频时间为唯一基准，不以编辑器操作时间或渲染时间为基准。

### 2.3 HUD 变化服务课程理解

事件不应只是装饰动画。每个事件都应帮助学员理解当前阶段、当前任务、当前重点或下一步行动。

### 2.4 最终视频无交互

事件渲染结果是 MP4 画面的一部分。即使阶段条、地图节点在编辑器里可点击跳转，最终视频中也不可点击。

## 3. 基础数据结构

以下为产品层字段定义，供后续前端和渲染工程细化。

### 3.1 TimelineEvent

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 事件唯一 ID |
| type | enum | 是 | 事件类型 |
| startTime | timecode | 是 | 触发时间，格式建议为 HH:MM:SS.mmm 或秒数 |
| endTime | timecode | 否 | 结束时间，提示类事件建议填写 |
| duration | number | 否 | 持续秒数，可由 endTime 推算 |
| targetModule | enum | 是 | 目标模块 |
| title | string | 否 | 事件标题 |
| body | string | 否 | 事件正文 |
| refId | string | 否 | 关联阶段、任务、地图节点或能力点 ID |
| state | enum | 否 | 目标状态 |
| priority | number | 否 | 同一时间多事件冲突时的显示优先级 |
| enabled | boolean | 是 | 是否启用 |

| id | string | 是 | 阶段唯一 ID |

| defaultTaskId | string | 否 | 对应默认任务 |
| defaultHintId | string | 否 | 对应默认提示 |
| status | enum | 否 | 未开始、当前、已完成，由播放时间推算 |

### 3.3 MapNode

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 地图节点 ID |
| label | string | 是 | 节点名称 |
| stageId | string | 否 | 对应课程阶段 |
| unlockTime | timecode | 否 | 点亮或解锁时间 |
| status | enum | 否 | 未开始、当前、已完成、锁定、解锁 |

### 3.4 TaskItem

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

| 字段 | 类型 | 必填 | 说明 |

| title | string | 是 | 提示标题 |
| body | string | 是 | 提示正文 |
| startTime | timecode | 是 | 出现时间 |
| endTime | timecode | 否 | 消失时间 |
| stageId | string | 否 | 对应阶段 |

## 4. 事件类型

### 4.1 stage_change：底部课程阶段条变化

用途：

1. 更新底部课程阶段条当前阶段。
2. 标记之前阶段已完成。
3. 标记后续阶段未开始。

触发方式：

1. 到达某个 CourseStage.startTime。
2. 或用户手动添加 stage_change 事件。

目标模块：

1. bottom_stage_bar。
2. 可联动 course_map 和 task_tracker。

显示效果：

1. 当前阶段高亮。
2. 已过阶段点亮或完成。
3. 未来阶段灰色或低亮。

注意：

底部课程阶段条不是播放器进度条，不显示可拖动滑块，不显示播放控制。

### 4.2 map_node_activate：课程地图节点点亮

用途：

显示课程路径推进到了哪个节点。

示例：

1. 05:00 点亮「信源导入」。
2. 10:00 点亮「导演椅」。
3. 15:00 点亮「技能释放」。

目标模块：course_map。

状态变化：

1. 未开始 -> 当前。
2. 当前 -> 已完成。
3. 锁定 -> 解锁。

联动规则：

1. 如果节点绑定 CourseStage，则阶段进入当前时地图节点同步高亮。
2. 地图节点点亮时，可触发任务切换或能力解锁，但第一版可以通过独立事件配置。

### 4.3 hint_show：重点提示弹出或切换

用途：

强调当前片段最重要的知识点、避坑点或行动提醒。

目标模块：

1. focus_hint。
2. 可选 bottom_status_hud。

提示类型：

1. key_point：重点内容。
2. beginner_tip：新手重点。
3. warning：警告或避坑。
4. summary：阶段总结。
5. homework：作业或行动提醒。

字段要求：

1. title 必填。
2. body 必填。
3. startTime 必填。
4. endTime 或 duration 建议必填。
5. priority 建议填写。

显示约束：

1. 单条提示文案应短。
2. 不应遮挡主视频关键内容。
3. 同一时间多条提示冲突时，优先显示 priority 更高的事件。

### 4.4 task_update：任务状态切换

用途：

显示当前操作任务或学习任务，让课程成为任务推进式学习。

目标模块：task_tracker。

状态变化：

1. 未开始。
2. 当前。
3. 已完成。

典型场景：

1. 00:00 当前任务为「理解本节课目标」。
2. 04:00 当前任务切换为「上传资料」。
3. 10:00 当前任务切换为「点击 Customize」。

规则：

1. 同一时间建议只有一个当前任务。
2. 新任务成为当前任务时，上一个当前任务默认变为已完成，除非用户另行配置。
3. 当前任务文案必须短于重点提示文案，便于扫读。

### 4.5 skill_unlock：能力点解锁

用途：

把知识点包装成游戏化能力模块，增强学习完成感。

目标模块：

1. bottom_status_hud。
2. 可选 course_map。
3. 可选 focus_hint。

示例：

1. 06:00 解锁「听众定位」。
2. 09:00 解锁「目标设定」。
3. 12:00 解锁「焦点聚合」。

字段要求：

1. title：能力点名称。
2. body：能力点说明，可选。
3. refId：能力点 ID，可选。

显示方式：

1. 短暂显示解锁提示。
2. 可在地图或底部 HUD 中保留已解锁状态。

### 4.6 stage_summary：阶段总结

用途：

在阶段结束或关键节点帮助学员建立结构感。

目标模块：

1. focus_hint。
2. bottom_status_hud。

示例：

1. 09:50 显示「阶段完成：你已经完成信源导入」。
2. 14:50 显示「阶段完成：你已经掌握 Customize 的核心逻辑」。

触发时间：

1. 通常发生在阶段结束前或结束时。
2. 可由用户手动配置。

显示约束：

1. 不应与下一个阶段开场提示冲突。
2. 持续时间应足够阅读。

### 4.7 homework_reminder：作业或行动提醒

用途：

把课程从“看完”转化为“实际操作”。

目标模块：

1. focus_hint。
2. bottom_status_hud。
3. 可选 task_tracker。

示例：

1. 22:00 显示「课后任务：上传一份自己的资料」。
2. 23:00 显示「行动清单：用私人教练模板生成一次 AI 播客」。

规则：

1. 通常出现在阶段末尾或课程末尾。
2. 可以同时将任务追踪切换为「课后行动」。

### 4.8 layout_toggle：模块显示状态切换

用途：

在特定时间显示或隐藏某些辅助模块。

目标模块：

1. right_sidebar。
2. focus_hint。
3. teacher_window。
4. bottom_status_hud。

第一版建议：

1. 作为 P1 或 P2。
2. 不建议用户频繁使用，避免画面跳变过多。

## 5. 阶段条、地图、任务的联动规则

### 5.1 默认联动

当播放时间进入某个 CourseStage：

1. 底部阶段条将该阶段标记为当前。
2. 之前阶段标记为已完成。
3. 后续阶段标记为未开始。
4. 如果阶段绑定 mapNodeId，则对应地图节点标记为当前。
5. 如果阶段绑定 defaultTaskId，则任务追踪切换为该任务。
6. 如果阶段绑定 defaultHintId，则可显示对应重点提示。

### 5.2 手动事件优先

如果用户在同一时间配置了独立事件，则独立事件优先于默认联动。

示例：

阶段进入「信源导入」时默认任务是「上传资料」，但用户在同一时间配置 task_update 为「选择资料来源」，则任务追踪显示「选择资料来源」。

### 5.3 冲突处理

同一时间多个事件冲突时：

1. 按 priority 排序。
2. 同模块同类型事件只显示最高优先级。
3. 不同模块事件可以同时发生。
4. 提示类事件不宜同时显示多条，除非 UI 明确支持堆叠。

## 6. 时间格式规范

第一版内部可使用秒数，界面显示建议使用：

1. MM:SS，适用于 1 小时以内课程。
2. HH:MM:SS，适用于长课程。
3. 毫秒精度可保留但不强制暴露给普通用户。

示例：

1. 03:20。
2. 10:00。
3. 01:05:30。

## 7. 编辑器中的事件操作

用户应该可以：

1. 新增事件。
2. 删除事件。
3. 修改事件类型。
4. 修改触发时间。
5. 使用当前视频时间写入触发时间。
6. 修改事件文案。
7. 修改目标模块。
8. 修改持续时间。
9. 点击事件跳转到触发时间。
10. 禁用事件但保留配置。

## 8. 渲染时事件计算

渲染时，系统按主视频时间计算每一帧或每个采样点的 HUD 状态：

1. 根据 CourseStage 判断当前阶段。
2. 根据 TimelineEvent 判断模块状态。
3. 根据事件优先级处理冲突。
4. 将当前时间对应的 HUD 状态渲染到视频画面。

最终成片只保留视觉结果，不包含可交互数据。

## 10. 第一版验收标准

时间轴事件能力达到可验收状态，需要满足：

1. 用户可以手动配置阶段开始时间。
2. 用户可以手动配置至少 7 类事件。
3. 用户可以用当前播放时间写入事件时间。
4. 预览画面能根据时间显示正确 HUD 状态。
5. 阶段条、地图和任务能按配置联动。
6. 提示类事件能按持续时间显示和消失。
7. 最终 MP4 中所有事件表现为画面变化，不出现播放器控件。
