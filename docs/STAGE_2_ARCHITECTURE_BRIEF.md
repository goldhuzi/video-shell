# 第 2 阶段工程架构简报

## 1. 阶段目标

第 2 阶段的目标是把第 0 阶段产品定义和第 1 阶段界面设计，转化为后续开发 Agent 可直接执行的工程架构依据。

本阶段只输出工程架构文档，不正式开发产品功能，不实现完整 React 编辑器，不实现完整 Remotion 渲染器。

本阶段需要明确：

1. 系统整体边界。
2. 编辑器与渲染器的分离关系。
3. 配置驱动的数据流。
4. 时间轴驱动的 HUD 状态计算方式。
5. 第一版推荐技术栈。
6. 项目目录、数据模型、素材管理和渲染流程。

## 2. 产品工程定义

《视频课程套壳》的工程核心不是剪辑、播放或托管，而是：

> 基于本地课程配置文件和主视频时间轴，预览并渲染一套游戏化课程 HUD 的 16:9 视频生成系统。

工程上应拆成两个主要运行面：

| 运行面 | 面向对象 | 主要职责 | 是否进入最终 MP4 |
| --- | --- | --- | --- |
| 本地可视化编辑器 | 课程创作者 | 导入素材、编辑配置、预览时间点、触发渲染 | 否 |
| Remotion 渲染器 | 渲染流程 | 读取配置、计算帧状态、合成视频和 HUD、输出 MP4 | 是 |

编辑器和渲染器共享配置模型、组件语义和状态计算逻辑，但不共享编辑器控件。

## 3. 系统边界

### 3.1 第一版系统包含

1. 本地 Web 编辑器。
2. 课程配置 JSON。
3. Zod 配置校验。
4. 固定 16:9 最终视频 HUD 布局。
5. 主课程视频素材引用。
6. 讲师视频或头像素材引用。
7. 课程阶段配置。
8. 时间轴事件配置。
9. 编辑器内播放器预览控件。
10. Remotion MP4 渲染流程。
11. 本地输出目录。

### 3.2 第一版系统不包含

1. 数据库。
2. 用户登录。
3. 云端 SaaS。
4. Electron 桌面壳。
5. OBS 插件。
6. 课程平台能力。
7. 多轨剪辑能力。
8. AI 自动识别章节或重点。
9. 最终视频播放器控件。
10. 自由画布设计器。

## 4. 编辑器与渲染器分离原则

### 4.1 共同输入

编辑器和渲染器都以同一份 `LessonProjectConfig` 为核心输入。

配置文件应包含：

1. 课程信息。
2. 讲师信息。
3. 媒体素材引用。
4. 布局配置。
5. 主题配置。
6. 课程阶段。
7. 地图节点。
8. 任务列表。
9. 重点提示或提示素材。
10. 时间轴事件。
11. 渲染配置。

### 4.2 编辑器职责

编辑器负责让用户方便地创建和修改配置：

1. 读取主视频并显示预览。
2. 显示最终视频画框。
3. 在画框中渲染 HUD 预览层。
4. 允许用户点击 HUD 模块。
5. 在右侧属性面板编辑被选中模块。
6. 在底部时间轴配置阶段和事件。
7. 使用当前视频时间写入配置字段。
8. 校验配置并展示错误。
9. 保存或导出配置。
10. 触发本地渲染脚本。

编辑器中的播放、暂停、拖动、时间显示和选中框，只属于编辑器 UI，不属于最终视频。

### 4.3 渲染器职责

渲染器负责把配置和素材转成最终 MP4：

1. 读取 `LessonProjectConfig`。
2. 使用 Zod 校验配置。
3. 解析主视频、讲师视频和头像路径。
4. 根据 FPS 和当前帧计算 `currentTime`。
5. 根据课程阶段和时间轴事件计算当前 HUD 状态。
6. 渲染 MainVideoFrame 与 HUD 组件。
7. 输出 1920 x 1080 MP4。

渲染器不得渲染编辑器工具栏、属性面板、播放器控件、选中框、时间轴表格或任何编辑器辅助 UI。

## 5. 配置驱动原则

第一版所有业务状态都应来自配置，而不是写死在组件中。

工程实现时应遵守：

1. HUD 文案来自配置。
2. 阶段状态由配置时间和当前时间推算。
3. 事件状态由 `TimelineEvent` 计算。
4. 组件显示模式来自布局配置。
5. 素材路径来自媒体配置。
6. 渲染参数来自渲染配置。

允许组件内写死的是第一版固定布局框架、默认主题 token、默认动效时长和兜底空状态。

## 6. 时间轴驱动原则

主课程视频时间是唯一时间基准。

编辑器预览和 Remotion 渲染都应复用同一类状态计算逻辑：

1. 输入 `LessonProjectConfig` 和 `currentTime`。
2. 先根据 `CourseStage` 推算默认阶段、地图和任务状态。
3. 再应用启用的 `TimelineEvent`。
4. 同模块冲突按 `priority` 处理。
5. 产出 `HudRuntimeState`。
6. HUD 组件只根据 `HudRuntimeState` 展示。

## 7. 推荐模块关系

```text
LessonProjectConfig
        │
        ├── Editor App
        │     ├── Video Preview Controller
        │     ├── Selectable HUD Preview
        │     ├── Property Inspector
        │     ├── Timeline Config Panel
        │     └── Save / Validate / Render Trigger
        │
        ├── Shared Schemas
        │     ├── Zod validators
        │     ├── TypeScript types
        │     └── timeline state calculation
        │
        └── Remotion Renderer
              ├── Composition
              ├── Media Loader
              ├── Frame to Time
              ├── HUD State Resolver
              └── MP4 Output
```

## 8. 第一版架构验收标准

第 2 阶段架构完成后，后续 Agent 应能直接开展：

1. 按目录结构初始化 Vite、React、TypeScript 和 Remotion。
2. 按数据模型创建 Zod schema。
3. 按编辑器架构实现本地可视化编辑器。
4. 按渲染流程实现 Remotion composition。
5. 按素材规范放置输入视频、头像和 HUD 资源。
6. 按时间轴模型实现 HUD 状态计算。

任何后续开发都必须继续保持编辑器与渲染器分离，继续保持配置驱动和时间轴驱动。
